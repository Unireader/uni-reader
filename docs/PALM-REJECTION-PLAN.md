# 防误触重做（安卓，模式1 / 模式2 共用）

> 2026-11-28 调研，同日按 §4.1~4.3 实现并实测（结果见 §7）。现状代码：`android/app/src/main/java/com/xvan/unireader/shared/TouchGuard.kt`（`PenProximity` / `FingerGate` / `PalmSettings`），
> 规则说明在 `android/AGENTS.md`「双指与防误触」。用户反馈：「现在感觉很死板」。

## 1. 现状：我们自己的规则

| 规则 | 做法 | 2026-11-28 一段日志里挡掉的手指 |
|---|---|---|
| 笔在附近 | 笔悬停中 / 离开 0.3 秒内，**所有**新手指都不认 | 36 次 |
| ② 写字时暂停单指滚动 | 笔 0.6 秒内用过，单指不滚动 | 36 次 |
| ③ 按手的位置屏蔽 | 笔 1.2 秒内用过，笔尖书写手一侧下方的单根手指不认 | 3 次 |
| ① 误触不甩惯性 | 短于 200ms、划不到 24dp 的单指划动不甩惯性 | — |
| 系统判为手掌 | `FLAG_CANCELED` → 结束手势、1 秒内的画面还原 | 1 次 |

死板的根源在前两条：**按时间一刀切、不看手指在哪**。另一只手想拖页面，只要笔还悬停着或刚写完字，就一律不认。

## 2. 实测：Pad 6 的硬件与系统已经替我们做了什么

### 2.1 触摸屏芯片（NVTCapacitiveTouchScreen，`/dev/input/event8`，`getevent` 原始数据）

- 报 `ABS_MT_TOUCH_MAJOR`（声明 0~255）：手指 5~7，手掌侧面 11~22。
- **芯片自己识别手掌**：手掌侧面按下后约 30ms，面积跳成 256（超出声明上限），随即结束这个触点（用户按了一两秒，芯片只报了 30ms）。系统据此发 `FLAG_CANCELED`。
- `ABS_MT_PRESSURE` 每个触点从头到尾固定为 1 / 32 / 50 之一：不是压力，是芯片给触点贴的标签，含义未明。
- 手掌平按会拆成 4~5 个小触点，面积 6~12，和手指相近（第一段录制，动作没有标注，属推测）。

### 2.2 小米系统（`MiuiEventBlockerManager`，`dumpsys window policy`）

- 对 UniReader 生效（`mCurrentFocusedWindow = com.xvan.unireader`，`mNativeEnableState = true`）。
- 笔连着时，手指先扣一段时间、移动超过阈值才放行：弱模式 40ms / 8px，强模式 64ms / 8px（配置 `/system_ext/etc/input/stylus_palm_reject_config.json`，562 个游戏不开）。
- `persist.stylus.palm.reject = 1`。
- **App 改不了**：没有公开接口。`mHasEditText` 一项暗示有输入框时会切强模式，未验证。

### 2.3 App 这一层拿到的（`ScratchCanvas.probeTouch` 临时探针，logcat `UniReader/Palm`「触点探针」）

| 信号 | 手指 | 手掌侧面 | 芯片判成手掌后 | 能不能用 |
|---|---|---|---|---|
| `getTouchMajor` | 0~1dp | 0~1dp | 10dp | 不能（系统按 GEOMETRIC 换算后太小） |
| **`getSize`**（= 原始面积 / 255） | **0.024~0.043** | **0.055~0.078** | **1.004** | **能** |
| `getPressure` | 0.00 / 0.03 / 0.05 | 同左 | 同左 | 不能（就是那三个标签） |
| `FLAG_CANCELED` | — | 约 335ms 后才到 | — | 能，但晚 |

- **写字时搭在屏幕上的手掌，几乎全被芯片和系统拦掉**：写一行字的过程中，App 只收到两个触点，存在 8ms（`getSize` 0.055 / 0.078），之后再没收到手指事件。
- **漏网的是「先放手掌、还没开始写」**：手掌侧面放下，App 收到 3 个触点，其中一个在 335ms 里移动了 140dp，系统才取消（画面被拖了一下再退回）；另一个 65ms 内 `getSize` 就从 0.031 涨到 0.078。

## 3. 小米 / 安卓有没有专属接口

- 小米：没有找到面向第三方的手写笔 SDK 或防误触接口；系统那套防误触是内部的。
- 安卓：只有「系统判定后取消」——`ACTION_CANCEL` / `ACTION_POINTER_UP` + `FLAG_CANCELED`（API 33 起），已接。
  参考：developer.android.com「Reject stylus palm touches」「Stylus palm rejection」。

## 4. 方案

原则：**手掌主要交给芯片和系统；App 只补它们漏掉的「先放手掌」那一下，而且先跟手、判错再退回，不再按时间把所有手指一刀切。**

### 4.1 去掉两条一刀切

- 删「笔在附近 → 所有手指不认」与「② 写字时暂停单指滚动」。
- 保留并改造「③ 按手的位置」：只挡书写手那一侧、笔尖附近的触点；另一侧的手指随时能拖、能缩放。

### 4.2 先跟手，判错再退回（推广现有的「系统判为手掌 → 还原」）

手指落下画面立刻跟着动（不加起手判定——用户否决过「先挪一段再判意图」）。手势进行中任一条成立 → 判为误触：结束手势、不甩惯性、画面退回落指之前：

| 判据 | 依据 |
|---|---|
| 系统 `FLAG_CANCELED` | 现有 |
| 任一触点 `getSize` ≥ 0.05（阈值待真机定） | 2.3 实测：手指 ≤ 0.043、手掌侧面 ≥ 0.055 |
| 手势开始后不久就落笔 | 先放手掌再写字的典型顺序 |
| 短时间内冒出 ≥ 3 个触点且挤在一起 | 手掌平按被拆成多个小触点（待确认） |

「退回」的时间窗沿用 `REVERT_MS = 1000`。

### 4.3 自动判断左右手

按「被判成手掌的触点在笔尖哪一侧」累计，自己得出书写手；`PalmSettings` 的「左手书写」改成自动、可手动覆盖。

### 4.4 界面

「小手」状态键保留：判为误触、在书写手位置被挡时照旧变灰并说明原因（`android/AGENTS.md` 的规矩：手指没反应必须说为什么）。

## 5. 验证

- 每条判据单独打点（logcat `UniReader/Palm`），记下判为误触时用的是哪条、当时的 `getSize` / 触点数 / 距落笔多久。
- 真机按五个动作逐项过：手指点 / 拖 / 双指缩放 / 先放手掌侧面 / 搭着手掌写字；再加一项「左手拖页面、右手笔悬停」。
- 手感由用户在真机上判，结论攒进 `docs/ANDROID-STANDALONE-PLAN.md §11.1`。

## 6. 还没确认的

- 手掌平按拆成的多个小触点：`getSize` 多大、App 能不能收到、收到多久。
- `getSize` 阈值 0.05 是否稳（手指重按、指腹平按时会不会超过）。
- 模式2 走同一份 `TouchGuard`，判据相同；Mac 那边不受影响。

## 7. 实现与实测结果（2026-11-28）

已按 §4.1~4.3 落地（`TouchGuard.kt` 的 `PenProximity.fingerVerdict` / `gestureVerdict` / `hoverRejects` / `systemPalm`，`PalmSettings.voteHand`；两块画布只换调用）：

- 去掉「笔在附近 → 所有手指不认」；② 写字暂停单指默认关（新键 `writePause2`）。
- 书写手区（③）：只在笔**悬停中或离开 300ms 内**生效（原 1.2 秒），区域加边界：往书写手一侧最远 220dp、往下最远 320dp。
  第一版沿用 1.2 秒、没有边界，日志里离上次用笔 474~1182ms、在笔尖右下方 23~248dp 的正常手指全被挡，用户报「刚写完字拖不动」。
- 落指挡 `getSize ≥ 0.05` / 认下第三根手指；手势中认下的手指 size 涨过阈值 → 作废、画面退回。
  「多处同时着屏」与手势中的面积判断**只算认下的手指**：被挡下、还搭在屏上的手掌不算，否则另一只手正常双指操作会被它连累。
- 左右手自动投票；手动切过「左手书写」就按手动。

### 7.1 提笔后约 460ms 手指没反应：芯片扣的，App 改不了

用户报「提笔后左手拖动至少 500ms 之后才有反应」（左手一侧 App 从来不挡）。同时录芯片原始触摸（`getevent`）与 App 日志对时：

| 笔离开悬停范围 | 芯片报出左手触摸 | App 收到 |
|---|---|---|
| 16:53:57.959 | +460ms | +19ms |
| 16:54:00.383 | +452ms | +19ms |
| 16:54:02.842 | +460ms | +29ms |
| 16:54:05.209 | +459ms | +20ms |
| 16:54:07.970 | +465ms | +21ms |

五次几乎一样 = 触摸屏芯片固定的等待（笔刚离开时不报手指）。驱动节点 `/sys/class/touch/touch_dev/` 下有 `pen_connect_strategy = 1`、`palm_sensor = 0`，
前者可能相关但没有文档；用户定**不去改硬件设置**，接受这段等待。
