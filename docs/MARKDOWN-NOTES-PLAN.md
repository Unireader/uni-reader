## 1. 引擎不用改，也不用 fork

`swift-markdown-engine` 0.9.0（`project.yml` 里钉死的那个版本）**本来就带 wiki 链接**，我们一处都没接：

| 引擎已有 | 说明 |
|---|---|
| 两形态存储 | 落盘 `[[名字\|<不透明 id>]]`，显示 `[[名字]]`；转换在 `WikiLinkService` |
| `WikiLinkResolver` | 三个方法：`resolve(displayName:range:) -> WikiLinkResolution?`（名字 → 稳定 id + 目标在不在）、`name(forID:) -> String?`（id → **当前**名字）、`fingerprint()`（目标集合变了就重排版） |
| `EmbeddedImageProvider` | `![[名字]]` 图片嵌入，字节由我们提供 |
| 未解析链接的样式 | `theme.incompleteLink`，解析不到的 `[[…]]` 自动是「断链」外观 |

⚠️ **两形态存储这一条我们刻意不用**（2026-09-20 第三次改版）：它要求把 id 写进文件，而用户要求
「不要改 `[[]]`」。我们只用 `WikiLinkResolver.resolve`（按名字判断链接通不通、点了去哪）与
`EmbeddedImageProvider`，`name(forID:)` 一律返回 nil。查证见 §3.1——**引擎不会自己往文件里加 id**。

## 2. 存储：新开一张 `md_doc` 表，**不动 `document`**

schema **v15**。

```sql
CREATE TABLE IF NOT EXISTS md_doc (
  id TEXT PRIMARY KEY,                       -- UUID，就是 [[名字|<id>]] 里的那个 id
  title TEXT NOT NULL,                       -- 显示名 = [[…]] 解析的名字（默认取文件名去扩展名）
  rel_path TEXT NOT NULL,                    -- 工作区相对路径，如 Notes/数学/极限.md
  group_name TEXT NOT NULL DEFAULT '',       -- 与 document.group_name 同义（一级分组）
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,                  -- 正文最后修改（离线镜像的 LWW 依据）
  last_opened_at TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_md_doc_path ON md_doc(rel_path);
```

正文**不进库**，就是 `<工作区>/Notes/…` 下的 md 文件本身（Obsidian 打开这个目录仍然是一个正常 vault）。

### 2.1 为什么不是「`document` 表加一列 `kind`」

一开始的直觉做法是给 `document` 加 `kind`（0=pdf / 1=md），毕竟用户要的是「与 PDF 并列」。不选它的三条理由：

1. **「并列」是界面语义，不是表结构语义。** `document` 一半的列对 md 是垃圾：`page_count` /
   `read_page` / `read_frac` / `read_zoom` / `read_hfrac` / `canvas_mode` 全是 PDF 阅读区的概念；
   `variant` / `location` 那套「一本书多个内容版本、按 content_hash 去重」更是为**不可变文件**设计的——
   md 是要被编辑的，每存一次 hash 就变，等于每存一次新增一个 variant。
2. **漏一处过滤就是一个 bug。** `workspace.documents` 现在有 8 处消费方（侧栏 / 参考窗 / 选文档弹窗 /
   MCP / 离线镜像面板 / `DocTabModel` / `RefCard`…），加了 kind 就得处处记得筛。这个项目已经在同类
   「真源要筛一道」的事情上栽过（`ocrRuns` vs `ocrVisibleRuns`、出图口漏传 `align`）。
   分两张表，**漏不掉**——老代码看不见 md 行。
3. **动 `document` 会让离线镜像的基线全体失效。** `MirrorFingerprint.specs` 里 `document` 的列顺序
   是写死的契约，加两列 ⇒ 每一行的指纹都变 ⇒ 升级后第一次同步，整张表被判成「两边都改过」，
   干跑预览里满屏无意义条目（正是 spec 注释里当初刻意避开 `last_opened_at` 的那种噪音）。
   新表没有历史基线，天然干净。

代价：侧栏要把两类条目合并显示。**这是我替用户做的设计决定，可推翻。**

> 2026-09-20 第三次改版后 `md_doc` 的定位又降了一档：它不再是「笔记的身份」（身份现在是
> `NoteRef` = 源 + 相对路径），只是**内建源的目录扫描缓存 + 记「上次打开」**。
> `group_name` / `sort_order` 两列随之**不再由导入填**——目录层级从文件路径推，见 §4。

### 2.2 跨端

- **安卓不动**（`android/` 是独立仓库）。安卓建的新库里没有 `md_doc`，Mac 打开时 `migrate()` 的
  `CREATE TABLE IF NOT EXISTS` 会补上；安卓读不到这张表也不影响它自己的功能。
- **离线镜像**：`MirrorFingerprint.specs` 加一条 `md_doc`（`lww: "updated_at"`），行级合并照既有规矩走。
  **md 文件本体**第一批按 `Images/` 那条纯 additive 通道复制（两边都有同路径文件时**不合并正文**，
  以 `updated_at` 新的那份覆盖，并在报告里列出来）。真正的 md 正文三方合并留到镜像批次，见 §6。
- `PROTOCOL.md` 不动：平板 / 网页端不参与 md 笔记（线格式没有这一类消息）。

## 3. 链接：按名字解析，**文件一个字不改**

🔴 2026-09-20 用户定：**文件里的 `[[…]]` 一个字都不许改**（原话「不要改 `[[]]` 现有的哪怕不兼容也不要改」）。
所以第一批那套「存 id、显示当前标题、改名不断链」**作废**，改成 Obsidian 本来的样子：

- **落在文件里的**：用户自己写的那些字，`[[极限的定义]]` / `[[数学/极限]]` / `[[极限|别名]]` /
  `[[极限#小节]]` / `![[attachments/图.png]]` —— 原样保留。
- **解析**（`NoteIndex.note(for:)`）：先**按原样**查一次（名字里本来就带 `#` / `|` 的笔记，如 `C#入门`，
  不该被收拾掉），不中再用 `MarkdownLink.linkTarget` 收拾一遍重来：去别名段（`|` 之后）、去锚点
  （`#小节` / `#^块`）、去 Markdown 转义。每一轮的次序是 ① 标题精确 → ② 相对路径去扩展名 →
  ③ 带扩展名的写法 → ④ 路径对不上时退回末段文件名 → ⑤ 忽略大小写。都不中 = 引擎画成断链，不报错。

  🔴 **这道收拾必须放在解析入口**，只在 `MarkdownLink.WikiParts` 里做不够——引擎那条路根本不经过它。
  引擎的解析正则 `[^\|\]…]*` 在**第一个竖线**处就切（不管前面有没有反斜杠），而且**不去锚点**，
  所以 `resolve(displayName:)` 收到的是 `名字#锚点\` 这种带尾巴的原串。表格里 Obsidian 把竖线写成
  `\|`（不转义会切断单元格），用户 2026-09-20 的 vault 里 47 条链接有 8 条是这样——修之前全是断链。
- **代价**（用户明确接受）：**笔记改名 / 挪目录，指向它的链接就断**。App 不会去改别人的正文来「修」它。
- **重名**：一个名字对多篇时取 `NoteRef.key` 字典序最小的那篇（稳定、可预期），并在导入报告里列出来。

### 3.0 🔴 引擎与 Obsidian 对**竖线**的理解正好相反

| | 竖线前 | 竖线后 |
|---|---|---|
| Obsidian | 目标名 | **显示别名** |
| 这个引擎 | 显示名 | **不透明 id**（它自己的格式是 `[[名字\|<uuid>]]`） |

后果（用引擎源码实跑出来的，`spike` 里 `wikiAliases` 那几条用例钉着）：

| 文件里写的 | 引擎显示成 | 递给 `resolve()` 的 |
|---|---|---|
| `[[名字]]` | 名字 | 名字 |
| `[[名字#锚点]]` | 名字#锚点 | 名字#锚点 |
| `[[名字\|别名]]` | **名字**（别名被吞） | **别名** |
| `[[名字#锚点\|别名]]` | **名字#锚点** | **别名** |
| `[[名字\\\|别名]]`（表格里转义竖线） | **名字\\** | **别名** |

所以**带别名的链接拿不到真名**——真名被引擎自己留着当显示文本了。解决办法是反过来建一张
**别名表**（`NoteIndex.aliases`）：扫一遍全部正文，把每条 `[[名字\|别名]]` 的别名登记到它指的那篇上
（`WorkspaceManager.registerAliases`）。用户 2026-09-20 的 vault 里 47 条链接有 36 条带竖线，
不补这张表就全是灰的、点不动。

🔴 **不能用 `name(forID:)` 去兜**：它一返回非 nil，`makeStorageState` 存盘时就会拿显示文本重拼存储形态，
`[[名字|别名]]` 变成 `[[别名|别名]]` —— 那是改文件。所以它**一律返回 nil**，代价是显示的是真名不是别名
（2026-09-20 用户看过实际效果后定「先不动」，要改就得 fork 引擎）。

### 3.1 点 `[[…]]` 跳转：引擎回调给的是**名字**，不是 id

`MarkdownASTStyler.styleWikiLink` 写的是 `.link = linkID ?? nodeName`。我们不往文件里写 id，
所以 `linkID` 恒为 nil，`onLinkClick` 回调拿到的永远是**文件里写的那个名字**。

🔴 因此路由入口 `WorkspaceManager.note(key:)` 必须认三种写法：`NoteRef.key`（`源:相对路径`）、
库里那行的 UUID、**以及名字**。

🔴 还有一处更阴的：**引擎的 `onLinkClick` 只在 `makeCoordinator()` 里捕获一次**，`updateNSView`
不刷新它。所以不能「先传空闭包占位、建完 `NSHostingView` 再换 `rootView`」——首次渲染发生在换之前的话，
协调器永久攥着那个空闭包。`MarkdownDocView` 用 `LinkRelay`（身份固定的中转闭包，目标随后填）绕开。

这两处任缺一个，表现都是**链接是蓝的、点了没反应**（2026-09-20 用户连报两次）。

### 3.2 引擎为什么不会偷偷改文件（查证过）

`WikiLinkService.makeStorageState` 写回存储形态时，那个 `|id` 取自 `.wikiLinkID` 属性，而该属性又是
`makeDisplayState` 从**存储文本的竖线后缀**解析出来的——**不是问 resolver 要的**。所以：

- 文件里是 `[[名字]]`（没有竖线）→ 编辑、存盘之后还是 `[[名字]]`；
- `WikiLinkResolver.resolve` 返回的 `id`（我们给的是 `NoteRef.key`）**只活在内存里**，决定这个链接
  画成可点还是断链、点了跳哪篇；
- `name(forID:)` 我们**一律返回 nil**：那是「把显示名替换成目标当前名字」的钩子，只对带 `|id` 的链接生效，
  而我们不写 id，也不该改别人正文的显示。

## 4. 两种笔记源

用户 2026-09-20：「我还希望有能够有引用模式，编辑远程的目录（非项目的）」。于是笔记有两种来源，
界面上一视同仁（侧栏各占一段，段里按**真实目录层级**多级展开）：

| | 内建（`NoteRootKind.workspace`） | 引用（`.reference`） |
|---|---|---|
| 文件在哪 | 工作区包里的 `Notes/` | 用户指的**外部绝对路径**（可以记几条，每台电脑用本机存在的那条，§10），App 不搬动它 |
| 怎么来的 | 「文件 › 导入笔记目录…」复制进来，或「新建 Markdown 笔记」 | 「文件 › 引用笔记目录…」挂上去 |
| 进不进库 | 进 `md_doc`，但那只是**扫描缓存 + 记「上次打开」** | 笔记**一行都不进**；源列表存 `meta.note_sources` |
| 同步（离线镜像 / 服务器） | 跟着工作区走 | 源列表 2026-10-29 起同步（§10）；外部目录里的内容由外部工具同步，App 不管 |
| 删除笔记 | 移到废纸篓 | 同样移到废纸篓，但确认框里会写清「这是工作区外你引用进来的目录」 |

🔴 **文件是真源**。`md_doc` 与目录每次 `refreshNotes()` 对账：文件多了就补行、没了就删行。
换句话说在访达里直接增删笔记，回到 App 刷新一下就对。

### 4.1 导入 = 整个目录原样复制

选一个目录 → 复制进 `Notes/<目录名>/`（撞名加 `-2`）→ 重扫 → 弹报告。

- **一个字节都不改**（红线）。md、附件、子目录全都照原样进来——所以 `![[attachments/图.png]]`
  这种写法照样显示得出来（附件**保持原相对路径**，不做内容寻址；那要改 `![[…]]` 里的文件名）。
- 跳过 `.obsidian/`、`trash/` 与一切 `.` 开头的目录。
- **原目录一个字节都不写**。
- 报告里会列出「导进来这批笔记里，`[[…]]` 指到的名字仍然解析不到的那些」——**只是告诉用户，不去改正文**。

### 4.2 `unireader://open?md=<…>`

两种写法都认：库里那行的 UUID（内建源才有），或 `NoteRef.key` = `<源 id>:<源内相对路径>`。

## 5. 分批

**第一批**（存储 + 导入 + 引擎接线）、**第二批**（界面）都在 2026-09-20 落地，当天又按用户三条新指令

### 落地了什么

- **存储**：`md_doc`（schema v15）= 内建源的扫描缓存；引用源列表存 `meta.note_sources`（2026-10-29 起同步，§10）。
- **纯逻辑**：`MarkdownLink`（只扫描：保护区 / `[[…]]` 目标名 / 图片引用 / frontmatter 别名）、
  `NoteTree`（`NoteRoot` / `NoteRef` / `NoteItem` / `NoteFolder` 多级树 / `NoteIndex` 名字解析）、
  `MarkdownImport`（路径与文件工具 + 整目录复制）。测试 `spike/markdown-link-test.swift`（66 项）。
- **执行层**：`WorkspaceManager+Markdown`（源管理 / 扫描对账 / 读写 / 新建 / 改名 / 删除 / 导入）。
- **界面**：侧栏每个源一段、按目录多级展开；标签页里编辑（`DocTabModel.noteRef`，与 `docID` 互斥）；
  `MarkdownDocView` + `MarkdownDocEditor`，自动保存三条（停手 0.8 秒 / 视图离开窗口 / App 退出）；
  「文件」菜单三项：**新建 Markdown 笔记**（⌘⇧N）、**导入笔记目录…**、**引用笔记目录…**；
  右键菜单（笔记：改名 / 在访达里显示 / 移到废纸篓；目录与段头：在这里新建 / 在访达里显示；
  引用源另有：改名 / 取消引用）。
- **跳转**：`unireader://open?…&md=<uuid 或 源:相对路径>`；`[[…]]` 单击在编辑区与页面气泡里都能跳。
- **正文搜索**（2026-09-21）：阅读窗工具栏的现有搜索框在 Markdown 标签里搜索当前笔记的显示文本；
  命中计数、上一个 / 下一个循环跳转、自动滚动与系统查找指示器均已接通。搜索只读，不改正文。

- **Agent 当前标签**（2026-09-21）：切到 Markdown 标签后，内置 Agent 的下一条消息会带上当前笔记身份；
  MCP get_state 能区分 PDF / Markdown / 空标签，get_current_view 能返回当前 Markdown 编辑器的实时正文
  与 revision（含尚未自动保存的改动）。update_markdown 用 revision 做乐观锁后替换完整正文，同时更新文件
  与所有正在显示这篇笔记的编辑器；用户在 Agent 读取后又改过内容时拒绝覆盖。
- **标签恢复**（2026-09-21）：`TabsModel` 的标签组保存格式升级为带类型的 PDF / Markdown 混合列表；
  重新打开 App 后恢复原顺序与原活动标签。旧版只含 PDF id 的记录继续兼容读取；PDF 仍懒装载，
  Markdown 后台标签只恢复 `NoteRef`，编辑器仍只为活动标签创建。

## 6. 红线

- 🔴 **任何自动维护都不许改笔记正文**（2026-09-20 用户定）。导入 / 改名 / 挪目录 / 扫描不得擅自改
  `[[…]]`、别名、锚点、附件名或标准链接。用户在编辑器里修改、或明确要求 Agent 通过 edit_markdown /
  update_markdown 修改正文属于显式编辑；工具只写 Agent 提交的内容，不替它“修复”任何链接。
- **导入不改原目录**，引用模式更是只读原处编辑——一个字节都不写回用户 vault 之外的地方。
- **md 正文只走文件，不进库**。`md_doc` 是内建源的扫描缓存，以文件为准，对不上就按文件重建。
- **引用源里的笔记不进库**（§4）。~~引用源列表不同步~~：2026-10-29 用户定改为同步——每个目录记几条路径、
  每台电脑用本机存在的那条，「外部路径是这台机器的事实」由多路径解决（§10）。
- **`md_doc` 与 `document` 不混表**（§2.1），也不要为了图省事在 `document` 里塞 md 行。

## 8. 外部改动跟随 + 切标签保留滚动位置（2026-09-24）

- **监听**：`App/NoteFileWatcher`（FSEvents 文件级事件，主线程回调，latency 0.3s）一个工作区一个，
  盯全部源的根目录（内建 `Notes/` + 引用的外部目录），`refreshNotes()` 末尾按根目录清单重建（根没变不动）。
  路径一律 `NoteFileWatcher.canonicalPath` 口径（`realpath` + Unicode 组合形式）——🔴 别用
  `URL.resolvingSymlinksInPath()`，它会把 `/private` 去掉，和 FSEvents 报上来的对不上。
- **分流**（`WorkspaceManager.noteFilesChanged`）：隐藏文件、`.part`、以及**内容与 `selfWrittenNotes`
  相同的 md**（自己存盘引起的）一概不理——否则打字时每 0.8 秒一次自动保存就要重扫一遍。其余：
  结构指纹（各源的文件 + 目录清单，`noteSignature`）变了 → 整个 `refreshNotes()`（侧栏跟着变）；
  只是正文变了 → 在 `noteBaseIndex` 上重登别名，不重建侧栏。正文变了都发 `.markdownNotesChangedOnDisk`。
- **开着的那篇**（`MarkdownDocView.reloadFromDisk`）：听到自己的文件变了就重读换上；
  🔴 **本地还有没存下去的输入时以本地为准**（不换，稍后自动保存照常写盘）——两边同时改只能留一边，
  选了不让用户正在打的字消失的那一边。
- **滚动位置**：窗格切标签会把整个 `MarkdownDocView` 拆掉重建，引擎协调器里的偏移跟着没了。
  引擎留了 `onPersistScrollOffset` / `restoreScrollOffset` 两个口子，存进 `MarkdownDocView.ScrollMemory`
  （按 documentId，App 活着期间有效，不落库）；另在 `viewWillMove(toWindow: nil)` 先记一次，
  不依赖托管视图什么时候真正释放。

  - 引用目录的根不在这台电脑上 → 拒绝（不在本机凭空建目录）；服务器镜像源只读 → 拒绝。

## 15. Agent 改名 / 挪目录：MCP `rename_markdown`（2026-11-12）

起因：用户「继续完善下 Agent 能力，比如 markdown 笔记支持重命名」。此前 Agent 能建、能改正文，改名只能让用户在侧栏右键做，或者绕过 App 直接 `mv` 文件（标签页会当成那篇没了直接关掉）。

- **工具**（`.write`，受写入开关管）：目标同 `edit_markdown`（`note_ref` / `window_id` / `workspace`，省略 = key 窗口里那篇）；

  `source`（挪去别的源，如内建 `Notes/` ↔ Obsidian 目录；同日第二轮加）。至少给一个。

  **换源**跨文件系统：先复制到新位置、核对大小一致，再把原件**移到系统废纸篓**（红线 11 先留底再删）；原件挪不走就删掉刚复制的那份、报错（等于没动）。
  换源时 `folder` 不给 = 新源里同样的相对目录。附件不跟着走（`![[图]]` 按文件名全库找，一般照样显示）。
- **规则**（`WorkspaceManager.moveNote(_:title:folder:)`，纯规则在 `MarkdownImport.movedNotePath`）：
  - 只改名不挪：留在原目录；只挪不改名：**文件名一个字不动**（`a#b.md` 不会被洗成 `a-b.md`）；改名时扩展名照留（`.markdown` 不变 `.md`）。
  - 名字 / 目录规则同 `create_markdown`（`newNotePath` 拆成 `noteFileName` + `noteFolderParts` 两半共用）。
  - 目标已有同名 → 报错、什么都不动，给出那篇的 `note_ref`；**只改大小写**（`abc` → `ABC`）不算撞名（APFS 默认不分大小写，`moveItem` 改得了）——
    界面上的「重命名…」原来会把这种情况误报成「已存在」，一并修了。
  - 服务器镜像源只读、引用目录不在这台电脑上 → 拒绝。
- 🔴 **断链只报告、不改**（红线 9）：改名前留一份 `[[…]]` 索引快照（`WorkspaceWikiIndex.snapshot()`），改完再取一份，

## 19. 中文表格按版面宽度折行（2026-11-13，引擎 fork）

用户定：「中文表格要不要自动折行：需要做一下」。

- **原来**：引擎按 CSS 自动表格布局算列宽，列的最小宽度 = 最长的「不能断开的词」，而词只在空格处断。中文句子不带空格，
  一整句被当成一个词，最小宽度就是整句的宽度，所以稍长一点的中文表格一律超出版面、横向滚动（§18 之前的截图就是这样）。
- **现在**：中文 / 日文 / 韩文旁边也可以断行，断在哪儿按 Unicode 换行规则（系统自带的 ICU 断行，`，` `。` `）` 不放行首、`（` 不放行尾）；
  英文仍只在空格处断（`well-known`、网址不受影响）。版面放得下最小宽度时，表格就收进版面宽度、格子里折行；列很多、最小宽度都放不下时照旧横向滚动。
- **影响**：笔记里已有的中文表格排法会变（原来横向滚动的会收窄折行）；Agent 回复、习题里的表格同样。Perch 用同一个引擎，升级后也会这样。
- 测试：引擎 `CJKTableWrappingTests` 5 项（断点位置、标点不落行首、英文不受影响、窄版面折行、短表格保持原宽）；离屏样张 340 / 520 宽看过。
- 实测清单（用户）：
  161. 笔记里一张句子较长的中文表格：收进版面宽度、格子里折行，不再横向滚动；拖窄窗口跟着重新折行；标点不出现在行首。

## 20. 拖选经过表格的样子；单元格编辑框；行列手柄（2026-11-13，引擎 fork）

用户：「表格从上下行还是框选就会出现这个蓝色的高亮，还没有修复」（截图：一大块蓝色从表格上面的空行盖到下面，宽表格右边一截没盖住）；
「表格的输入框优化下样式，现在有点丑，比较生硬」（截图：深色实底、直角细边框）；「表格的行列抓手很难触发手形鼠标，放上去就是输入的竖线」。

- **拖选的高亮**：§18 只解决了「选区停在表格中间」，高亮仍是系统画的——在 TextKit 看来整张表是**一行**，行高 = 表格高 + 上下间距，
  选中时系统把这一行从左到右整条涂满。现在：系统高亮跳过选区里的表格 / 块公式**以及紧挨着它们的空行**，表格自己在图片下面画选中色，
  形状就是表格的圆角底（宽表格画在它的横向滚动层里，跟着滚动、两端圆角）；文字照常是系统高亮。窗口不在前台 / 编辑区没有焦点时和系统一样变灰。
- **编辑框**：原来编辑框是一块实底——编辑区本身透明，编辑框只能退回系统的文本底色（深色下近黑），和表格的浅灰底对不上，再加一道直角边框。
  现在编辑框**没有底色**：打开某一格时，表格按「这一格不画字」重新出一张图，编辑框里的字正好落在原来的位置，像直接在格子里改；
  外圈是系统焦点颜色（半透明强调色）的圆角框，圆角跟表格样式走。顺带修了边框颜色一直是黑色的问题。
  第一版是「在同一张图上改要藏哪一格、再叫显示它的视图重画」，用户实测：刚打开时两份字叠在一起（编辑框和图片行高略不同，越往下错得越开）、
  换到下一格时上一格变成空白——屏幕上的图总落后一步，一打字（表格整张重画成新图）就对了。离屏测试没抓到：测试出图会让每个视图当场重画。
  改成和拖动改宽度同一条路：编辑框打开 / 换格 / 关闭时把表格重新出一张**新图**（藏哪一格算进图片缓存的键），打字写回时出的图也一开始就藏好。
- **手柄**：鼠标在手柄上时，文字视图每动一下都把光标设回输入竖线，盖掉了手柄的手形。现在手柄上显示手形；能点中的范围比画出来的小药丸
