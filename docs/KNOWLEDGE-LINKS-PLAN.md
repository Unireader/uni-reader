# 知识关联：笔记 · 书页 · 批注互相引用

> 2026-11-12 用户：「希望加上图支持，让一个学科的知识串起来，Markdown 笔记 + PDF 内容 + PDF 文字注解，这些都能相关关联引用」；
> 「在输入的时候输入链接即可有一个弹窗可以搜索选择要链接的，比如用 `[[xxx]]` 链接那么就输入 `[[` 弹出一框来选」。
> 同日拍板四条：**关系只从文字里认**（不加关系表）、先做「关联」面板（关系图以后再说）、**一个工作区 = 一个学科**、笔记里加 `[[书名#page=12]]` 写法。
> 之前讨论过 SurrealDB 当可选后端，否决（工作区库是三端契约、Swift 端无法嵌入、强项我们已有），见当日对话。

## 1. 关系从哪来（不另存）

| 写在哪 | 写法 | 指到 |
|---|---|---|
| 笔记 / 批注正文 | `[[笔记名]]`、`[[笔记名#标题]]`、`![[笔记名]]` | 笔记 |
| 笔记 / 批注正文 | `[[书名]]` | 整本书 |
| 笔记 / 批注正文 | `[[书名#page=12]]`（Obsidian 链 PDF 的写法；`书名.pdf#page=12&…`、`|别名` 都认） | 书的第 12 页 |
| 笔记 / 批注正文 | `unireader://open?…&doc=…[&page=…][&note=…]`（行内链接 / 尖括号 / 光秃的都认） | 书、书页、某条批注 |
| 笔记 / 批注正文 | `unireader://open?…&md=…` | 笔记 |
| （结构） | 批注挂在它那一页上 | — |

- 🔴 App 自己**从不往正文里加链接**（红线 9）。加关系 = 用户在笔记 / 批注里写一个链接（`[[` 候选帮着写），或者用户让 Agent 用 `edit_markdown` 写。
- 不改数据库结构，平板 / 服务器 / 离线镜像不受影响；Obsidian 打开同一份笔记也读得懂（`[[书名#page=N]]` 在 Obsidian 里指 vault 里同名 PDF）。
- 习题、画板本轮不进关联（习题笔记里的链接以后可以照样认）。

## 2. 解析（`NoteIndex.target(for:)`，`Sources/App/NoteTree.swift`；类型 `LinkTarget` 在 `Sources/App/KnowledgeLinks.swift`）

- `[[…]]` 的索引里加了**书单**（书名归一化、小写、去 `.pdf` → 文档 id；同名挑 id 小的）。重扫笔记时带上；书库变了（导入 / 改名 / 删）
  `WorkspaceManager.refresh()` 直接换书单（`WorkspaceWikiIndex.updateDocuments`），不用重扫笔记。
- 页码也认简写 `#p=12`（2026-11-13：Agent 在日程说明里这么写过，原来点了只打开书、不跳页）。
- 次序：**带 `#page=` 的先当书找**，找不到再当笔记；不带的**先当笔记**（同名时笔记优先，老链接一个都不变），再当书；最后查别名表。
  书名里本来就有 `#` 的（`C#入门`）整串也试一次。
- 别名表改存「链接目标」：`[[书名#page=3|第三页]]` 的别名「第三页」指到那一页（引擎把别名当 id 递给解析器，点击时回调的也是别名）。
  `MarkdownLink.wikiAliases` 多给竖线前那段（含锚点）。
- 编辑器 / 气泡：`WorkspaceWikiIndex.resolve` 对书与书页也返回「存在」，画成可点的链接。

## 3. 输入 `[[` 弹出选择框（`NoteLinkCompleter`）

整页笔记、笔记小窗、**批注编辑框、图片笔记说明框**（后两个原先没接，TODO 第 7 条的尾巴）都用它。候选三层：

1. **名字对得上的**：笔记（`[[笔记名]]`）、书（`[[书名]]`）、**同一工作区开着的 PDF 正在看的那一页**（`[[书名#page=N]]`，排最前——边看书边记笔记最常用）；
   打了 `书名#12` / `书名#page=12` 就给那本书的那一页。
2. **按正文搜出来的**（两个字起，停手 0.15 秒再查，走全工作区搜索索引，`SEARCH-PLAN.md`）：
   书里的某页 → `[[书名#page=N]]`；批注 → `[引文前 24 字](unireader://…&page=…&note=…)`（批注没有名字，用 Markdown 链接）；笔记里的某一段 → `[[笔记名#标题]]`。
3. 书名里有 `[` `]` `|` 写不进 `[[ ]]` 的，改写成 `[书名](unireader://…)`。

- 第一次按正文搜时让索引在后台对一遍（不等），刚改的笔记 / 新加的批注也搜得到。
- 弹框沿用 Agent 输入框 `@` 那块（系统菜单材质、不抢焦点）；行图标新增 `AgentMention.symbol`（书 `book.closed`、书页、批注、笔记段落各一个系统符号）。
- 🔴 小编辑器（`MarkdownNoteEditor`）要经 `LinkedEditor` 用 `@ObservedObject` 盯着候选对象：选中后替换请求放在 `pending` 里，不重算视图引擎就收不到。
- 🔴 **↑↓ / 回车 / Esc**（2026-11-12 用户实测报「不能用方向键选择」）：引擎只在「光标在一条 `[[…]]` 里」为真时才把这几个键交给候选列表，
  而这个状态要由我们给一个**能写的** `isWikiLinkActive` 绑定（`NoteLinkCompleter.wikiActive`）；两个编辑器原先都没给（引擎默认常量 false），
  方向键一直归编辑器。11-10 的候选列表起就是这样。`spike/note-link-complete-test.swift` §4 复现并锁住。

## 4. 存与读（`SearchIndex` 的 `edge` 表 + `KnowledgeGraph`）

- 链接**原样**记在搜索索引库的 `edge` 表（`来源键 / 从哪 / 第几行或第几页 / wiki 还是链接 / 括号里那串 / 原文 / 那一行`），
  随笔记（`md:`）与批注（`ann:`）来源一起重建；**读的时候**再按此刻的笔记清单与书单解析——改名、导入新书都不用重建。表结构版本 4。
- `KnowledgeGraph.load`：只对笔记与批注两类来源对账（`SearchIndex.refreshLinks`，不碰 PDF 页文字；不删别的前缀的来源），读全部 `edge`，在主线程外解析。
- 🔴 **这一路与全量建索引各跑各的**（2026-11-12 用户实测报「批注里引用了，关联列表看不到」）：输入 `[[` 的候选为了按正文搜会启动全量建索引，
  几本几百页的书要好一阵；原先笔记 / 批注的对账排在它后面、等 3 秒就放弃，关联页拿到旧链接、之后又没人叫它重取。现在：
  ① 链接那一路单独跑（`refreshLinks`，`linksRunning`）；② 全量那轮也先做笔记、批注、习题、上下文，整本书的文字最后；
  ③ 笔记 / 批注的来源一写进索引就发 `.searchIndexLinksChanged`，关联页收到就重取（内容没变不重建）。`spike/search-test.swift` §5c 复现并锁住。
  日志：`[关联] 读链接：N 条，认出 M 条，书单 K 本，对账完成 / 未完`（`~/Library/Logs/UniReader-ws.log` 存在才写）。
- 链出用**实时**内容：正在编辑的那篇用编辑器里的正文（没存盘的也算），正在看的那页用标签里的批注；被引用的从索引来。
- 「指到这一页」= 直接链这一页的 + 链到这一页上某条批注的（拷贝批注链接时不带页，按这一页上的批注 id 认）。

## 5. 「关联」面板（Inspector 新一页，`link` 图标）

- **PDF 标签**：标题「第 N 页的关联」；分四组：这一页的批注链到 / 引用了这一页 / 引用了这本书（整本、别的页、别的批注，注明第几页）/
  其他页的批注链到（注明批注在第几页）——停在别的页也看得到这本书的全部关联（2026-11-12 用户实测后补）。
- **Markdown 标签**：标题「「笔记名」的关联」；两组：这篇笔记链到 / 反向链接（带行号）。
- 每行：图标 + 名字（笔记名 / 书名 · 第 N 页 / 批注 · 书名 · 第 N 页），第二行是链接所在那一行的文字；点了打开（笔记在本窗口开，书页 / 批注走 `DeepLinkRouter.open`）。
  指不到的显示「找不到：…」、点不动。都没有时提示怎么加（输入 `[[`）。
- 刷新：翻页、换标签、本书批注改了、任何地方存了笔记（`.markdownNoteSavedInApp`）、索引里笔记 / 批注的链接变了（`.searchIndexLinksChanged`）都重取；
  停手 0.25 秒；**内容没变不重建列表**（自动保存每 0.8 秒一次，列表别跟着闪）。
- 卡片沿用 Inspector 的 `InspectorCard`，文字一律 `labelColor`（红线 4）。

## 6. 打开链接（四处统一）

点 `[[…]]`（整页笔记、笔记小窗、批注气泡）与「关联」面板的行都先 `WorkspaceManager.linkTarget` 认，笔记就在当前窗口开，
书 / 书页 / 批注走新的 `DeepLinkRouter.open`（找标签 / 挑窗口用 `showDocument` / `showMarkdown`，定位与展开同 `unireader://` 链接）。
`unireader://` 的行内链接本来就由系统打开、回到链接路由，不变。

## 7. MCP

- 新工具 **`links`**（`.read`）：给 `note_ref` / `document_id`（+ `page`）/ `annotation_id` → 链出（`outgoing`）与被引用（`incoming`）；整本书的被引用 = 指到它任一页、任一条批注的；
  `all` = 整个工作区的全部关联（给 Agent 梳理一个学科）。每端带 kind / 身份 / 标题 / 链接。
- `markdown_links`：`[[书名#page=N]]` 不再报成断链，结果多给 `document_id` / `page`。
- `instructions` 与 Agent 面板上下文写明三种写法与 `links`。
