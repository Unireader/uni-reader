# 日程（日历 + 待办，Agent 帮着排计划）

> 2026-11-13 立项并落地第一轮（Mac + 服务器同步；安卓只跟上数据）。schema **v26**。

## 1. 起因与定案

用户：「能不能帮我出一个内置日程表，AI 帮我去安排一些计划方案。我做好后就可以更新，类似于日历 + 待办那种」。
同一轮又提：「agent 还需要加一些统计工具，用于统计各种数量，避免读取全部内容来统计数据这种情况」——统计工具见 `MCP-PLAN.md §38`，
排计划时 Agent 先用它看进度。

问过后用户选（全是推荐项）：

| 问题 | 定案 |
|---|---|
| 存在哪 | **每个工作区一份**，存工作区库、随服务器同步（一个工作区一门科目，计划跟着科目走；Agent 排计划时能直接看这门课的书、笔记、习题进度） |
| 界面放哪 | **单独的「日程」标签页**（月历 + 选中那天的待办 + 详情）+ **Inspector「今天」页**（读书时直接打勾） |
| Agent 的计划怎么进日程 | **直接写进日程**，整份计划可以一键删掉（先进回收站）；用户做完打勾、写一句做得怎样，Agent 据此调整 |
| 安卓 | 这轮**只跟上数据**（能同步、回收站认得、不出错），平板界面下一轮 |

## 2. 数据（v26）

两张新表，DDL 在 `Sources/Store/LibraryStore.swift`（搜 `v26：日程`），🔴 安卓 `Schema.kt` 逐字相同。

- `schedule_plan`：`id`、`title`、`goal`（要达成什么）、`agent`（排它的 Agent；用户建的为空）、`created_at`、`updated_at`。
- `schedule_item`：`id`、`plan_id`（空 = 不属于哪份计划）、`title`、`detail`（Markdown，可写 `[[书名#page=12]]`）、
  `day`（`YYYY-MM-DD` 本地日历日，空 = 没排日期）、`start_min`（当天第几分钟，-1 = 不定时）、`duration_min`（0 = 没说）、
  `done_at`（ISO 8601，空 = 没做完）、`result`（做完后写的一句「做得怎样」）、`seq`（同一天里的先后）、`agent`、`created_at`、`updated_at`。
  索引：`day`、`plan_id`。
- **日子是字符串**：学习计划按「哪一天」排，跟时区无关；字符串直接比大小就是先后（过期 = `day < 今天 AND done_at = ''`）。
  换算全在 `ScheduleDay`（公历、本机时区，用户系统日历是农历也按公历算）。
- **事项与书 / 笔记的关系只从 `detail` 里的链接认**，不另存关系表（同 `KNOWLEDGE-LINKS-PLAN.md` 的规矩）。
- 同步：两张表进 `MirrorFp.specs`（`agent_turn` 之后、`meta` 之前，都按 `updated_at` 取新），跨端向量 #38 #39（`spike/mirror-fp-vectors.txt`）。
  `plan_id` 没有外键：合并时两张表各管各的行；事项指向的计划不在了（别处删了）就当「不属于哪份计划」显示。
  服务器经符号链接编同一份 `Sources/Store/`，升级到带 v26 的服务器才能同步日程（旧服务器上传不了这两张表，App 照常用）。
- 刷新：写库的地方一律发 `.scheduleDidChange`（object = 工作区）；同步拉到这两张表（`applyRemoteRows`）、离线副本合并完、回收站放回也发。
  日程页、Inspector「今天」、侧栏「日程」那一行听它。

## 3. 纯逻辑（`Sources/App/ScheduleText.swift`）

纯 Foundation，`spike/schedule-test.swift` 直接编：

- `ScheduleDay`：字符串 ↔ 日期（不存在的日子如 2 月 30 日认不出）、加减天 / 月、两天差几天、星期几、月历 42 格（按系统「一周从哪天起」）、所在那一周。
- `ScheduleTime`：`HH:mm` ↔ 当天第几分钟。
- `ScheduleText.links`：说明里的 `[[…]]`（去重、保持先后；跨行、空的不算）。
- `ScheduleText.agentLine`：随新对话第一句话带给 Agent 的那一行（§7）。
- `ScheduleFocus`：打开日程时要去哪一天、选中哪一件；`rowID = "schedule"` 是侧栏 / 标签组持久化的键。

执行层 `Sources/App/WorkspaceManager+Schedule.swift`：读（按日子范围 / 计划 / 过期 / 没排日期 / id 前缀）、写（建计划、加一批事项、整行改、打勾、挪日子），
删除先归档（§5）。加事项时同一天里排在已有的后面；挪到别的日子的排到那天最后；跟库里一样的不写（免得 `updated_at` 白变、同步白传）。

## 4. 界面

### 4.0 入口与标签页

- **侧栏最上面一行「日程」**（行尾是今天「做完 / 共几件」，打勾时只重画这一行，不重建侧栏）。
- **Inspector「今天」页**的「打开日程」，点某一件也打开日程并选中它。
- MCP `open_schedule`（Agent 带用户去看某一天 / 某一件）。
- 日程是标签页内容的第五种（与 PDF / Markdown / 画板 / 习题互斥，同习题的做法：开之前 `select(nil)`）。**一扇窗口至多一个日程标签**
  （`TabsModel.openSchedule`：开着就切过去，当前标签空着就就地开，否则新开）。标签组持久化（键 `schedule`）、冷启动恢复、工具栏「返回」/ ⌘[ ⌘]
  （`NavPlace.Target.schedule`）都认它。看的是哪一天、选中哪一件记在标签上（`DocTabModel.scheduleShownDay` / `scheduleSelectedItem`），
  切走再切回来接着看那一天；MCP `get_state` / `get_current_view` 报 `content_type = schedule`（后者带 `day` / `item_id`）。

### 4.1 月历（`Window/Schedule/ScheduleMonthView`）

顶上一条（`ScheduleTabView`，同习题标签的写法：`headerView` 材质）：‹ › 换月、「今天」、月份；右边「计划」下拉、「请 Agent 安排…」。
下面左边是月历：一行星期 + 6 周 × 7 天，每格列出那天的事项（定了时间的带时间、做完的划掉、放不下的写「还有 N 件」）；
今天的日子用强调色加粗、旁边一个小圆点；选中的那天整格底色。

- 一整个视图自己画：格子是内容排版，不是在仿系统控件；颜色全用系统语义色，深浅色自动跟。
- 点格子 = 选这一天；点格子里的一件 = 选中它；双击格子 = 选这天并把光标放进「添加」框。
- **拖**：格子里的一件、右边列表里的一行都能拖到别的格子（挪日子）。

### 4.2 事项列表（`Window/Schedule/ScheduleDayList`）

右边上半：那天的日子（今天加「· 今天」）、「添加」输入框（回车加一件到这天，光标留在框里连着加）、事项列表：

- 那天的事项；**看的是今天时**下面再列「过期没做完（N）」（带原来的日子）；最后是「没排日期（N）」。
- 每行：勾选框（打勾 = 做完）+ 标题（做完的划掉）+ 一行小字（时间 · 时长 · 计划名）；说明放在悬停提示里。
- 右键：标记为完成 / 未完成、挪到（今天 / 明天 / 后天 / 下周一 / 不排日期）、删除…；键盘：空格打勾、Delete 删除。可多选。

### 4.3 详情（`Window/Schedule/ScheduleItemEditor`）

右边下半，选中一件时显示（窗口矮时可滚动）。2026-11-13 用户看了第一版说「详情这里优化下 UI，还有 md 支持」（说明是一小块原文框，
`[[…]]` 列成的按钮一行排不下、最左边那个被截掉），改成表单式：

- 勾选框（打勾 = 做完）+ 标题（大一号、折行、直接点着改）；下面一行小字：所属计划 · 谁排的。
- 日期 / 时间 / 时长三行，左边标签右对齐成一列。
- **说明平时显示排好版的 Markdown**（`AgentMarkdownView`：列表、粗体、公式、表格都排）；`[[…]]` 显示成「书名 · 第 N 页」这样的链接
  （`ScheduleText.displayMarkdown`：只是显示时换，库里原文不动；代码里的不换），点了在本窗口打开那篇笔记 / 那本书的那一页
  （`AgentBlockContext.openLink` 接过点击）。点「编辑」换成原文输入框（随内容长高，最多 320），「完成」/ Esc 收回去；没写说明时按钮是「添加说明」。
  原来那一行链接按钮去掉了。
- 做得怎样（折行的输入框）；最底下删除… + 完成时间。
- 链接页码也认 `#p=N` 简写（Agent 写过，`KNOWLEDGE-LINKS-PLAN.md §2`）。

**改了就存**：文字框打完（离开框）存、选择类控件当场存、换选中 / 切走前存。库里重读回来时正在打字的框不被覆盖。

### 4.4 Inspector「今天」页

Inspector 顶部分段多一页「今天」（`checklist` 图标，不挑标签种类）：今天的日子与「做完 N / 共 M」、「打开日程」；一个「加一件今天的事」输入框；
今天的事项卡片（勾选框 + 标题 + 小字，点卡片 = 到日程里看这一件；右键：标记完成、挪到明天 / 今天、在日程中显示）；
「过期没做完（N）」+「全部挪到今天」。内容没变不重建（别处每改一次都会通知），输入框加完一件光标留着。过了零点自动换天。

### 4.5 计划

「计划」下拉列出每份计划（「名字  做完 / 共」），子菜单：目标、转到下一件没做的、**请 Agent 调整这份计划…**、删除这份计划…（连同名下的事项）。

## 5. 删除（回收站，红线⑪）

日程页删事项 / 删计划、MCP `delete_schedule` 都**先归档再删**：新种类 `schedule`（`Trash.Kind.schedule`），快照里 `schedule_plan` + `schedule_item`
两张表（计划名下的事项一起带上）；manifest 计数 `schedulePlan` / `scheduleItem`（安卓同名）。放回用 `OR REPLACE`（两张表都没有子表）。

## 6. MCP（批 8，`MCP-PLAN.md §37`）

- `list_schedule`（`.read`）：默认今天起 14 天 + 全部过期没做完的 + 没排日期的；`plan_id` 看一份计划的全部；`status` all / open / done。
  每件带 `item_id`、`plan_id`、`day`、`start`（`HH:mm`）、`duration_minutes`、`done`、`done_at`、`result`、`overdue`、`agent`；计划带进度与首末日子。最多 500 件。
- `add_schedule_items`（`.write`）：`plan`（title + goal，新建一份计划）或 `plan_id`（加进已有的）或都不给（零散事项）；`items` 最多 300 件，
  日子 / 时间格式不对直接报错（不悄悄丢掉）。
- `update_schedule_items`（`.write`）：只改给了的字段——挪日子（空 = 不排日期）、改时间（空 = 不定时）、改标题 / 说明 / 时长、打勾 / 取消、写结果、换计划；
  `plans` 改计划名字 / 目标。一项不对整批不动。
- `delete_schedule`（`.delete`）：事项、或整份计划连同名下事项，先进回收站。
- `open_schedule`（`.write`）：给用户打开日程，去某一天 / 选中某一件。
- id 都认完整的或 8 位以上前缀。`instructions` 里加了日程与统计两句。`workspace_stats` 的 `schedule` 一块给计数（见 §38）。

## 7. Agent 上下文

- **每段新对话第一句话**随工作区记忆带一行（`ScheduleText.agentLine`）：今天几件、做完几件、过期几件、几份计划，今天的事列几条，提一句用哪几个工具。
  没有日程（今天没事、没过期、没计划）就不带。
- **活动标签是日程时**，每条消息的上下文块多一行 `Current tab: Schedule (日程), looking at <day>`（选中了哪一件也带上），后面接一句工具提示。
- **「请 Agent 安排…」**：把一句话放进这扇窗 Agent 输入框（「帮我安排一下接下来几天的学习计划。」，用户可改了再发），隐藏说明里写怎么排：
  先 `workspace_stats` + `list_schedule` + 记忆看进度，目标 / 期限 / 每天多少时间不清楚就先问，提一个简短方案，再用 `add_schedule_items` 写成一份计划
  （每件一个具体任务、一天的量要现实、说明里写页码链接或要做的题，别和已有的重复）。
  「请 Agent 调整这份计划…」另带 `plan_id`：读这份计划、看做完 / 过期 / 写了难的，用 `update_schedule_items` 挪后面的、`add_schedule_items plan_id` 补新的，做完的不动。
